# Чеклист после утечки секретов в репозиторий

Если API-ключи, пароли SSH или токены когда-либо попадали в git или в общие markdown-файлы, считайте их скомпрометированными.

## Обязательные действия

1. **Отозвать и перевыпустить** в панелях провайдеров:
   - Anthropic, OpenAI, Brave Search, Resend
   - GitHub personal access token (если использовался)
   - Любые ключи из смежных проектов (DeepSeek, Gemini и т.д.), если они фигурировали в том же репозитории
2. **Сервер (VPS):** сменить пароль root или отключить вход по паролю и перейти на **SSH-ключи** (`ssh-keygen`, `ssh-copy-id`, в `sshd_config`: `PasswordAuthentication no` после проверки входа по ключу).
3. **Проверить биллинг** провайдеров API на аномальный расход.
4. **Удалить секреты из истории git** (если репозиторий уже публиковали): `git filter-repo` / BFG или создать новый репозиторий без истории — иначе ключи остаются в коммитах.

## Где хранить дальше

- Менеджер паролей (1Password, Bitwarden и т.п.)
- Секреты Paperclip только в UI **Secrets** (Seal / dropdown)
- Локальные пути к файлам с ключами **не** указывать в markdown внутри репозитория

## Этот репозиторий

Файлы `API_KEYS_REFERENCE.md`, `DEPLOYMENT_READY.md`, `DEPLOY_WITH_EXISTING_KEYS.md` и содержимое `VERIFIND_KEYS_REFERENCE.md` приведены к **шаблонам без значений**. Реальные значения нужно вставлять только локально или в секрет-хранилище, не в git.
